# Strict schema contracts

Run `make validate-schema-contracts` and `make test-schema-contracts` from the
repository root. `validate-schemas` requires both, and is required by `check-all`,
`precommit` and `prepush`. CI runs them in the existing `Test Go` job and the
dedicated `Schema Contracts` check on every push and pull request, without path
filters. Repository branch protection should require `Schema Contracts`.

## Validator and bootstrap

The isolated module is assessed from its own module root by
`make lint-schema-contracts` and both Git hooks. Root-module staged-package lint
does not cross this module boundary. The required module assessment covers format,
lint and (for push/full gates) security without modifying source files.

The isolated tooling module pins `github.com/santhosh-tekuri/jsonschema/v6`
**v6.0.3** and `gopkg.in/yaml.v3` **v3.0.1**, with transitive versions and module
checksums in `go.mod` and `go.sum`. It shares the strict engine used by goneat,
without adding tooling dependencies to the public Go module.

The Make target downloads and verifies the locked modules, builds
`bin/schema-contracts` with `GOWORK=off`, read-only module selection and
`GOPROXY=off`, and prints its executable path and Go build identity. The
executable checks its engine/parser versions and rejects replacements. There is
no PATH binary or goneat fallback. Provision the Go module cache with
`make bootstrap-schema-contracts` before disconnected operation; subsequent
validation and tests need no network. Go's checksum database authenticates
bootstrap downloads against the checked module sums.

Resolver inputs are the engine's embedded, module-checksummed draft 4, 6, 7,
2019-09 and 2020-12 metaschemas, plus the checked inventory's schema resources
and explicit URI aliases. Every other load fails, including `file:` references.
Aliases enumerate existing publication/retrieval spellings; no hostname or
filename guessing happens at runtime. Unknown dialects, duplicate resource IDs,
unsupported required vocabularies and unresolved references fail validation.
Subschemas, including unreferenced definitions, are compiled as well as roots.
Application annotations are not traversed as schema positions.

## Inventory contract

`inventory.json` is reviewed source, not a file regenerated by the gate. Its
expected path set must exactly equal every `.json`, `.yaml` and `.yml` candidate
under root `schemas/`, `config/`, and the corresponding TypeScript, Python and
Rust distribution directories. Go embeds the canonical roots directly. This is
the published schema/config corpus; build configuration, documentation examples
and language test fixtures outside these roots are not schema publication roots.

Each path has an explicit classification and provenance:

- `schema`: declared dialect or explicitly inherited dialect, including boolean
  schemas. Filename suffix and `$schema` presence do not determine classification.
- `metaschema`: distributed dialect definitions, compiled in isolated contexts.
  They do not override the engine's trusted resolver. This also permits the
  separately distributed 2019-09 offline variant with the same published ID.
- `data`: named catalogs/defaults/instances with owners. An application `$schema`
  must match its manifest target and is validated as an instance, including the
  seven vendored classifier dimensions.
- `excluded`: named, owner-attributed, SHA-256-locked invalid fixtures or example
  envelopes/streams. Any byte change requires explicit review of the exclusion.
- `wrapper`: checked source path and byte-for-byte parity. Wrapper resources do
  not create duplicate IDs in the canonical catalog. Use `make sync` to update.

No symlinks are followed: file, directory, root and ancestor links all fail,
including cycles. Directory/read/parse errors fail visibly. JSON must be valid
JSON; duplicate keys, non-string YAML keys, aliases and multiple YAML documents
are rejected outside explicit hashed exclusions. No discovery error is ignored.
Numeric YAML scalars retain full decimal precision. Underscores and leading plus
signs are normalized textually; hexadecimal/octal/binary integers use arbitrary
precision conversion. Non-finite or otherwise unsupported spellings fail explicitly
instead of being coerced through floating point.

To add or move a published asset, update its explicit entry and supported wrapper
entries, then run both targets. A zero inventory, missing expected path or new
unclassified candidate fails. The tests use miniature inventories to exercise
YAML data/schema distinction, bare `.json`, boolean and inherited schemas,
discovery failures, reference closure and semantic negative controls through the
production Make target.

## ADR metadata migration

The lifecycle schema's `$id`, dialect, seven enum values and annotation payload
are preserved. Metadata is now application annotation data under
`x-adr-metadata`, not subschemas under `definitions`:

| Previous JSON pointer             | Replacement JSON pointer             |
| --------------------------------- | ------------------------------------ |
| `/definitions/statusDescriptions` | `/x-adr-metadata/statusDescriptions` |
| `/definitions/sortOrder`          | `/x-adr-metadata/sortOrder`          |

Descendant pointers move with these roots. Raw-schema readers must migrate their
lookups; unchanged instance-validation behavior does not preserve the old JSON
pointers. No compatibility copy remains under `definitions`.

Tests reconstruct the original schema and verify its SHA-256, compare metadata
and remaining root content deeply, reject the original with a semantic
`deprecated` keyword diagnostic, and exercise all seven lifecycle values through
both the lifecycle schema and the frontmatter schema's offline reference. The
required Make target is also exercised with a malformed keyword-type control.
