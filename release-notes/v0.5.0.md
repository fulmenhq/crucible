# Release v0.5.0

**Schema contracts are now enforced offline against an exact inventory of every published schema and wrapper copy, the ADR lifecycle schema moves its metadata under `x-adr-metadata`, several published configuration shapes gain schemas or optional fields, and tag signing and release publication run against committed public pins.**

## Overview

A tooling and contract-hardening release. `make validate-schema-contracts` compiles every published schema offline with a strict engine, checks the exact set of published paths (schemas, data files and wrapper copies), and fails on discovery errors. Six published configuration shapes gain schemas or optional fields so that the shipped configuration validates against its declared schema. Release signing, verification and publication tooling reads committed public key pins and fingerprint anchors.

## Why This Matters

**For raw-schema readers (anything that reads `adr-lifecycle-status.json` as data, not through a validator):** the lifecycle metadata moved. Instance validation is unchanged; JSON pointers are not.

| Previous JSON pointer             | Replacement JSON pointer             |
| --------------------------------- | ------------------------------------ |
| `/definitions/statusDescriptions` | `/x-adr-metadata/statusDescriptions` |
| `/definitions/sortOrder`          | `/x-adr-metadata/sortOrder`          |

The `$id`, dialect, the seven status values and the metadata payload are unchanged. No copy remains under `definitions`.

**For similarity-fixture consumers:** the `similarity` v1.0.0 schema returns to the `distance`, `normalization` and `suggestions` categories with a single distance case definition. The split-metric contract is in the `similarity` v2.0.0 schema, which is unchanged.

**For fixture-catalog consumers:** `taxonomy/fixture` v2.0.0 validates scenario arrays and the current catalog declares it. The v1.0.0 schema is unchanged and still validates variant maps. Choose the schema from `$schema`, not from `version`.

**For release operators:** tag creation, verification and publication read the committed key pins, fingerprint anchors and tagger identity from the tagged commit, and require an independently supplied approved OpenPGP primary fingerprint.

## Highlights

### Offline schema contract enforcement

- Every published schema compiles offline under its declared dialect; remote references are resolved from bundled metaschemas and a checked catalog.
- An explicit inventory (`scripts/schema-contracts/inventory.json`) lists every published schema, data file and wrapper copy. A zero inventory, a missing path or an unclassified candidate fails.
- Wrapper copies must match their source byte for byte; `make sync` updates them.
- A `Schema Contracts` workflow runs the validator and its tests on every change.

### Configuration contracts

- `branding/v1.0.0/ecosystem.schema.json` is new and describes `config/branding/ecosystem.yaml`.
- Exit-code entries accept optional `signal_catalog`, `linux_calculation` and `macos_calculation` strings.
- Server-management, site-branding and site-styling accept optional root `$schema`, `version` and `description`.
- `taxonomy/fixture/v2.0.0/fixture-catalog.schema.json` is new.
- The signals fixture uses `fallback_behavior`, `log_template` and `operation_hint` consistently.

### Signed tags and release publication

- Committed public pins: the OpenPGP release key (primary plus one signing subkey), the minisign public key, fingerprint anchors and the tagger identity. See `docs/security/README.md`.
- `make release-tag` creates a signed tag with the committed tagger and deletes it locally if it fails the pinned check. `make release-push-tag` pushes only the tag and confirms the remote object and GitHub verification.
- The minisign attestation pair is required and checked against the committed pin.
- `scripts/release-publish-assets.sh` stages by default and publishes as a separate step. See `docs/release/publication.md`.
- A read-only `Release trust verification` workflow runs on `v*` tags. A passing run is a consistency signal, not release authorization.
- `docs/security/README.md` records the retired OpenPGP identity and the historical tag ranges.

### Toolchain

- goneat v0.6.8, installed into `bin/` through an sfetch v0.4.12 bootstrap whose engine digest and signatures are verified; a mismatch fails before anything runs.
- Go 1.26.11 (module floor and CI), Bun 1.4.3, `js-yaml` 4.3.2, `@biomejs/biome` 2.5.14, `vitest` and `@vitest/coverage-v8` 4.1.11, `ruff` 0.17.0. GitHub Actions are pinned by commit SHA.
- `make precommit` installs locked JavaScript dependencies first and then runs sync and checks in order.
- The TypeScript wrapper's `VERSION` and `CRUCIBLE_VERSION` report the release SemVer; they previously reported `2025.10.0`.

### Documentation

- The trademark notice states that 3 Leaps, LLC is a North Carolina LLC.
- Bootstrap, secrets, CDRL, AI-agent and foundry interface documents are updated.
- The bootstrap guide and repository operations SOP describe the check-only `precommit` and `prepush` profile (`goneat assess --mode check --hook pre-commit|pre-push`) for consumer repositories, and defer Go toolchain selection to the consumer's declared reference toolchain.

## Breaking Changes

**None** to schema ids or version paths. Raw-schema readers of `adr-lifecycle-status.json` must use the new JSON pointers above. Consumers holding the earlier `short`/`extended`/`full` branding shape must migrate to the motto-based shape that `ecosystem.schema.json` describes.
