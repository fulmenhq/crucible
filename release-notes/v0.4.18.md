# Release v0.4.18

**A documentation patch: the draft technical manifesto is removed (inbound links retargeted to live architecture docs; no replacement manifesto), and the forge workhorse standard is aligned with Roan, loopback-by-default, and required request-id middleware.**

## Overview

A documentation-only patch release. The headline is retiring the aging draft technical manifesto and pointing inbound links at the live architecture documents that already describe the ecosystem. There is no replacement manifesto. Historical release notes that mention the manifesto are left unchanged.

The same cut aligns the Fulmen Forge Workhorse Standard with the landed Rust workhorse: Roan (Rust / rsfulmen) is a canonical language variant, Tuvan (TypeScript / tsfulmen) is listed, the unused Clydesdale example is removed, `{PREFIX}HOST` defaults to `127.0.0.1`, and HTTP workhorses MUST honor, generate, and echo `X-Request-ID` using the existing logging and HTTP REST specs. The workhorse standard remains draft.

This is a **documentation** patch: no FulmenHQ public API changes, no schema version bumps, and no new features.

## Highlights

### Draft technical manifesto retired

The draft manifesto is deleted. Inbound links that used to point at it now target live architecture documents (ecosystem guide, helper-library and forge standards, coding standards). No replacement manifesto is introduced. Historical release notes are unchanged.

### Workhorse standard — Roan, Tuvan, and Clydesdale

- **Roan** (Rust / rsfulmen) is recorded as a canonical language variant alongside Groningen (Go / gofulmen) and Percheron (Python / pyfulmen).
- **Tuvan** (TypeScript / tsfulmen) is listed in the canonical set.
- The unused **Clydesdale** example is removed.

### Loopback-by-default host

`{PREFIX}HOST` defaults to `127.0.0.1`. Binding `0.0.0.0` remains an explicit opt-in. The workhorse standard remains draft.

### Request ID / `X-Request-ID` middleware required

HTTP workhorses MUST honor an inbound `X-Request-ID`, generate a UUID when the header is absent, echo the identifier on every response, and include it in structured request logs. This restates the existing logging and HTTP REST specs; no new module spec is introduced.
