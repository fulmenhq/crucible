# Release v0.4.18

**A documentation patch: the draft technical manifesto is removed (inbound links retargeted to live architecture docs; no replacement manifesto), and the forge workhorse standard is aligned with Roan, loopback-by-default, and required request-id middleware.**

## Overview

A documentation-only patch release. The headline is retiring the aging draft technical manifesto and pointing inbound links at the live architecture documents that already describe the ecosystem. There is no replacement manifesto. Readers with a leftover manifesto bookmark should start at the Ecosystem Guide. Historical release notes that mention the manifesto are left unchanged.

The same cut aligns the Fulmen Forge Workhorse Standard with the landed Rust workhorse: Roan (Rust / rsfulmen) and Tuvan (TypeScript / tsfulmen) join Groningen and Percheron in the canonical breed set, `{PREFIX}HOST` defaults to `127.0.0.1`, and HTTP workhorses MUST honor, generate, and echo `X-Request-ID` using the existing logging and HTTP REST specs. The workhorse standard remains draft.

This is a **documentation** patch: no FulmenHQ public API changes, no schema version bumps, and no new features.

## Why This Matters

**For readers and anyone landing from an old link:** the 2025-10 draft technical manifesto is no longer a front door. A bookmark or inbound link that used to open that draft should start at the [Fulmen Ecosystem Guide](../docs/architecture/fulmen-ecosystem-guide.md). The layer cake, CRDL, helper/forge contracts, and coding/safety standards already live there (and in the documents it points to). There is no replacement manifesto. Historical release notes that mention the old file stay historical.

**For forge implementers and operators:** the workhorse standard now names **Roan** (Rust / rsfulmen) and **Tuvan** (TypeScript / tsfulmen) in the same canonical breed set as Groningen and Percheron — a Rust or TypeScript workhorse is a first-class variant, not an unnamed cousin. New HTTP workhorses default `{PREFIX}HOST` to `127.0.0.1` (binding `0.0.0.0` is an explicit opt-in) and MUST honor, generate, and echo `X-Request-ID` so a support dump can correlate one request across logs and responses. This restates the existing logging and HTTP REST specs. The workhorse standard remains draft.

## Highlights

### Draft technical manifesto retired

The draft manifesto is deleted. Inbound links that used to point at it now target live architecture documents (ecosystem guide, helper-library and forge standards, coding standards). No replacement manifesto is introduced. Historical release notes are unchanged.

### Workhorse standard — Roan and Tuvan in the canonical set

- **Roan** (Rust / rsfulmen) and **Tuvan** (TypeScript / tsfulmen) are in the same canonical breed set as Groningen (Go / gofulmen) and Percheron (Python / pyfulmen).
- A Rust or TypeScript workhorse is a first-class variant, not an unnamed cousin.

### Loopback-by-default host

`{PREFIX}HOST` defaults to `127.0.0.1`. Binding `0.0.0.0` remains an explicit opt-in. The workhorse standard remains draft.

### Request ID / `X-Request-ID` middleware required

HTTP workhorses MUST honor an inbound `X-Request-ID`, generate a UUID when absent, echo the identifier on every response, and include it in structured request logs. This restates the existing logging and HTTP REST specs; no new module spec is introduced.
