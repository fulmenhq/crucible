# Release v0.5.1

**A new `data` domain publishes the Tabular Exchange Standard, contract revision `tabular-exchange/0.1.0`: schemas for typed tables, rows, conversion policies and conversion results, with value, row, document and matching vectors and a fixture corpus that a reference checker validates in CI.**

## Overview

Programs that convert typed tables between file formats can describe a table, its cell values, the instructions for a conversion and the report a conversion produces in one shared form. A caller matches a conversion result to the output it describes and to the request that produced it, with separate verdicts for output agreement and for completion of the requested run.

The contract is **experimental** (ADR-0015). No implementation is qualified against `tabular-exchange/0.1.0` yet.

### For converter authors and consumers

- Pin the exact contract revision `tabular-exchange/0.1.0` and obtain it from a Crucible release that contains it. A published revision is never changed; every change, including a bound, is a new revision.
- Wire formats: `tabular-exchange.schema/0`, `tabular-exchange.policy/0` and `tabular-exchange.result/0`.
- Implementation detail goes in one bounded, namespaced `extensions` object. A result consumer ignores unknown namespaces; a policy reader refuses them.

## Highlights

### Tabular Exchange Standard

- Standard: `docs/standards/data/tabular-exchange.md`.
- Schemas (draft 2020-12, local `$defs` only) in `schemas/data/tabular-exchange/v0.1.0/`: `table-schema`, `row`, `conversion-policy`, `conversion-result`, with `$id` `https://schemas.fulmenhq.dev/crucible/data/tabular-exchange/v0.1.0/<file>`.
- Rules JSON Schema cannot express: `schemas/data/tabular-exchange/v0.1.0/semantic-validation.md`.
- Contract manifest, value, row, document and matching vectors, and fixtures in `valid/`, `invalid/` and `semantic-invalid/`: `config/data/tabular-exchange/v0.1.0/`.

### Validation

- `make validate-schema-contracts` compiles the new schemas, validates the `valid/` and schema-valid `semantic-invalid/` fixtures, and locks every intentionally invalid fixture by SHA-256.
- `make validate-tabular-exchange` runs a standard-library reference checker over every fixture and vector, fails on any disagreement or missing expectation, and runs regression controls for both. It is part of `validate-schemas` and the `Schema Contracts` workflow.

### Release tooling

- `make release-stage-assets` and `make release-publish` name each unset `FULMENHQ_CRUCIBLE_RELEASE_*` variable, and the release listing is retried after the draft is created. `RELEASE_CHECKLIST.md` documents the publication variables, steps and `dist/release/` contents.
